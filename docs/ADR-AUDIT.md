# ADR 审查记录

下表记录原 72 份历史 ADR 的代码核实依据与当前归宿。现行决策索引见 [CURRENT-DESIGN-DECISIONS.md](./CURRENT-DESIGN-DECISIONS.md)，领域术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 关键核实结果

- 旧配置历史承诺不成立。模板原地更新并加版本，删除后历史引用可悬空；工厂再次导出覆盖载荷。原 ADR 0040 合并入现行 [ADR 0006](./adr/0006-template-bound-to-integration-document-direction.md)，明确信息损失边界；原 0006 归档清理删除。
- 完整执行数量图不成立。当前只有结果到订单行的数量关系，回写复制包裹数量，没有包裹在多来源间的分摊。原 ADR 0013 清理删除，具体已实现的边界收口到现行 [ADR 0004](./adr/0004-source-level-fulfillment-results.md) 与 [ADR 0005](./adr/0005-source-order-may-write-back-multiple-parcels.md)。
- 全局商品别名和组合展开已经实现，通用波次覆盖、配置历史和候选冲突模型没有实现。原 ADR 0012 与 0022 清理删除，商品对齐冲突与数量拆分映射迁入 GLOSSARY.md。
- 文档类型和命名转换器有后端闭集校验，字段语义键没有。可控扩展语义与平台能力模型没有实现，原 ADR 0037、0041、0065 清理删除，扩展属性与平台概念迁入 GLOSSARY.md。
- 波次内直接授予不经过收件箱，输入文档是可选关联；波次关闭没有事件历史。旧的强制入口与历史假设清理删除，波次重开与归属移动概念迁入 GLOSSARY.md。
- 丢件再发由工厂沿原追踪标识回传新包裹，运营授予不再承担重发责任。现行见 [ADR 0009](./adr/0009-factory-handles-lost-package-resend.md)，丢件重发概念迁入 GLOSSARY.md。
- 无稳定来源单号的文件行被赋予 `fp:` 合成 ID，因此走稳定 ID 分支；无 ID 输入的窗口判定还要求来源时间。现行见 [ADR 0002](./adr/0002-configurable-duplicate-import-windows.md)。
- 客户主档与身份挂靠已落地，客户合并没有实现。现行见 [ADR 0012](./adr/0012-import-auto-creates-customer-profile.md)。Wails v3 桌面宿主与前端单一边界调用契约现行见 [ADR 0013](./adr/0013-migrate-to-wails-v3-beta.md)。
