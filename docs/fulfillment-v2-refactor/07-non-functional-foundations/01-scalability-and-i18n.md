# 可扩展性与多语言基础

> V2 的大数据查询和 i18n 是基础能力，不是后补优化。

## 大数据能力

### 核心原则

1. 查询真相由后端决定（排序/过滤/分页）
2. DTO 必须轻量（列表页最小字段，详情按需加载）
3. 页面模式可不同，但查询模型统一（`TableQueryState`）
4. 不能为大数据牺牲业务语义

### 分层接入

- 小数据页面保留本地方案
- 大结果集页面切远程查询
- 同一套查询状态模型可在两种模式切换

### 优先支持的页面

会员/买家列表、波次聚合总览、调整复核页、导出/回填/物流状态队列。


## i18n

### 应国际化

页面标题、按钮、表头、状态标签、toast、空状态、校验提示、导出模板字段名。

### 不应国际化

数据库主键、枚举 code、路由判断 code、业务规则键、profile key、source_channel 等稳定语义键。

### 最小范围

`zh-CN` + `en-US`。

### 对 Profile/Template 的影响

- `IntegrationProfile` 声明来源业务面和能力
- `DocumentTemplate` 负责具体语言/格式的字段映射
- UI 翻译由前端 i18n 系统管理
- 底层业务 code 保持语言中立

## 技术栈

继续沿用 Wails + Go + Vue/TypeScript + SQLite + 本地工作区。

### SQLite 偏好

- `journal_mode = WAL`
- 连接建立时统一设置 pragma
- 偏好沉到数据库初始化层，不污染领域模型

## 落地原则

1. 业务语义先稳定，语言再本地化
2. 查询状态先统一，页面模式再分化
3. 代码与枚举保持语言中立
4. 大数据与小数据方案可并存，底层抽象必须共享
