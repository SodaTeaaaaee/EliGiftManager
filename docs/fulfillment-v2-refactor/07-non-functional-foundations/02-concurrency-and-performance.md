# 并发假设与性能约束

## 并发模型

### 单写者假设

同一时刻只有一个应用实例写入同一数据库。桌面应用通过进程级文件锁保证独占。不设计分布式冲突解决。

Wails 单进程多窗口架构，多窗口共享同一 Go 后端，不构成并发写入问题。

### 未来多端同步扩展空间

树状历史天然适合多端（各端本地分支，同步时 merge/rebase）。`HistoryNode` 保留 `created_by`。未来同步层是独立模块。

### SQLite 约束

- WAL 模式
- `busy_timeout = 5000`
- 备份使用 Online Backup API 或 `VACUUM INTO`

## 数据规模预期

| 场景 | 参与者 | 履约行 |
|------|--------|--------|
| 典型 | 50–2000 | 200–10000 |
| 大波次 | 2000–20000 | 10000–100000 |
| 极端 | 20000–50000 | 100000–500000 |

活跃波次：1–3 个。历史节点/波次：20–200。

## 性能目标

### ReconcileWave 重算

| 规模 | 目标 | 策略 |
|------|------|------|
| < 10000 行 | < 500ms | 无感 |
| 10000–100000 行 | < 5s | 进度指示 |
| > 100000 行 | < 30s | 进度 + 可取消 |

批量写入，selector 预编译为 map 查找。

### 工作区历史

- Checkpoint：每 20 个 node
- 重放链长度 ≤ 20 步

### GC 策略

- `HistoryPin` 引用的 node 永不 GC
- 当前 head 所在分支祖先永不 GC
- 未 pin 旧分支：保留 30 天后可压缩（合并连续 patch 为 checkpoint）
