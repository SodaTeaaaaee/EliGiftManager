# 文档目标与重构基线

## 0. 文档目的

本文档定义 EliGiftManager 从"会员回馈发货工具"演进为"创作者履约系统"的重构计划。

新业务要求：
- **向前**：接入零售订单来源，同一平台可同时有会员和零售业务面
- **向后**：工厂回传发货状态和快递单号，系统需回填来源渠道

重构重点：统一业务语言、扩展数据结构、延长生命周期到"需求导入→分配→下工厂→回传物流→回填渠道"。

## 1. 备份分支

`backup/pre-fulfillment-v2-refactor-2026-05-12` — V2 重构前最后一个稳定基线。

## 2. 实施决策

采用 `main` 上的 greenfield 重建路线：
- **保留**：docs、备份分支、仓库历史、工程壳子与构建配置
- **丢弃**：旧业务代码、旧数据结构的连续演进假设、旧命名惯性

旧代码只保留在备份分支和历史文档中。
