# 测试、验证与验收

## 必测业务场景（41 项）

### 需求类型与分配
1. 纯会员波次 / 纯零售订单波次 / 混合波次
2. `policy_driven` 规则推导 / `demand_driven` 订单直入 / mixed wave 双路径
3. 平台权威已判定的阶段性会员礼物
4. 会员限定购买作为 `retail_order` 进入系统
5. 手工录入的会员权益 / 线下订单仍分别归入对应 `kind`

### 执行与物流
6. 多工厂平台同波次 / 工厂部分发货 / 多包裹
7. 物流回填成功 / 失败后重试
8. 会员无订单号 / 买家无会员身份

### 工作流与 UI
9. 会员地址晚于权益成立才补齐 / 通过表单补充款式/尺码
10. `excluded_manual` 单独统计不进入执行链 / `deferred` 后续重新纳入
11. 混合波次经 `Wave Overview` 汇总后进入共享调整层
12. 从 `Wave Overview` 直接跳过调整层进入后续阶段
13. 在 `Membership Allocation`/`Demand Mapping`/`Adjustment Review` 间来回跳转不破坏已有结果
14. 前置页面重算后，已确认的调整层例外仍被正确重放
15. 试图在调整层新增全新参与者时被阻止
16. 工厂导出后继续修改，给出提示但不锁死编辑
17. 物流导入后继续修改，给出偏离提示但不锁死
18. 前置重算导致例外失配时提示复核，不静默吞掉
19. 负数中间量不误报 review / 试图在调整层做 selector 动态批量修正被阻止

### 工作区历史
20. 从旧历史节点分叉后旧未来不丢失
21. 关闭软件再打开后历史可恢复
22. undo/redo 不伪装成已真实撤销外部动作
23. 文本输入框中 Ctrl+Z 优先原生撤销
24. undo/redo 后有即时 toast 和短期回执

### Basis 偏离
25. `drifted + recommended` 不被强行抬升成 `required`
26. adjustment target 被删除时进入 `drifted + required`
27. 不出现 `in_sync + required` 矛盾组合
28. UI 可投影为单一总结状态，底层保留双轴

## 回归重点

地址绑定、波次重算、商品快照与主档关系、用户覆盖、工厂导出模板、会员规则分配体验、输入采集与地址晚补、未纳入项统计、跨步骤往返数据稳定性、前置重算与调整层并存、导出/回传偏离提示、树状历史分支保留、持久化恢复后 head/basis 对齐、toast/回执一致性。

## 验收标准（25 项）

核心：同时承接会员和买家、来源追踪到需求单/行、持久化工厂提交和物流回传、物流回填独立追踪、波次状态反映完整生命周期、会员分配体验不劣化、平台权威判定不被本地重算、手工录入不被误建模成调整层、`Wave Overview` 独立承载导航和聚合、跨步骤跳转不破坏数据、调整层例外有保留规则、动态 selector 留在规则层、树状历史跨重启保留分支、drift/review 双轴独立。
