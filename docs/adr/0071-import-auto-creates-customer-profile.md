# 导入自动建立客户档案并写入收件地址

输入事实进入系统时，系统为它解析出一个客户档案，而不是把身份留在「未挂靠」状态等运营处理：

- 平台身份已挂靠到档案：用该档案。
- 平台身份是第一次出现：新建档案并把身份挂到它。档案名取模板映射的 `customer.display_name`（哔哩哔哩会员名单的昵称列），没有映射时退回身份值本身。
- 行里没有身份但有收件人（哔哩哔哩订单导出没有买家 UID）：如果某个档案的地址列表里已经有「收件人姓名 + 电话」都相同的地址，复用该档案；否则新建档案，名字取 `customer.display_name`（买家昵称），没有则取收件人姓名。
- 既没有身份也没有收件人：事实不挂档案。

行里的 `recipient.*` 字段写入解析出的档案的地址列表：按「收件人姓名 + 电话 + 地址第一行」去重，档案还没有地址时新地址标为默认。事实的 `ExtraData` 同时保留一份原始收件数据作为审计副本。

结果是零售订单导入后通常直接带上可用的收件信息快照，不再因为「收件信息不可用」阻塞；`InboxRow.Unattached` 仍然是派生字段，但现在几乎只在手工造出的悬空身份上为真。身份挂靠（`AttachIdentity`）保留，语义变成把身份从自动建立的档案改指到运营认定的档案：身份背后的事实、开放波次里的权益实例和未冻结的零售结果一起跟过去（未钉住的结果改用新档案的默认地址），已冻结的结果保持执行时的状态。被改指后空出来的自动档案不自动删除，由运营在资料库处理。第一期仍不做两档合并。
